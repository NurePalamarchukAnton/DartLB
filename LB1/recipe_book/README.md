# recipe_book (ЛР1)

Варіант 13 — рецепти й списки покупок.

## Як запустити

```bash
dart pub get
dart run
dart analyze
dart test
```

## Чому така структура

Зробив звичайний console-проєкт через `dart create`. У `bin/` тільки main, уся логіка в `lib/`, щоб потім можна було писати тести і не тягнути все з точки входу.

Файли в `lib/src/` розкидав по сенсу:
- `sample_data` — вхідні рядки і константи
- `parsers` — розбір CSV-рядка, маскування, список покупок, лічильник
- `validators` — перевірка діапазонів
- `aggregators` — фільтри, середнє, групування, сортування
- `report` — текстовий звіт

Класи не використовував, бо в першій лабі так і треба. Дані тримаю в records (`RecipeRecord`, `Ingredient`). Додав поле `addedAt` (дата додавання в збірку), щоб вік запису рахувався від реальної дати з вхідних даних, а не від hashCode.

## Чому такі типи

`parseLine` повертає запис з `recipe` і `error`, щоб не кидати exceptions на криві рядки. Числа й дату паршу через `tryParse`. Сортування має параметр `by` (`cookMinutes` або `ingredientCount`) і `ascending` — можна сортувати окремо за кожним критерієм. Лічильник повертає `(increment, read)`, щоб можна було прочитати значення, не збільшуючи його.

## Залежності

- `lints` — для `analysis_options.yaml` з recommended-правилами.
- `test` — для перевірок розбору й сортування, у `dev_dependencies`.

Пакет `path` прибрав: у ЛР1 шляхи не збираються, він лише приїхав із шаблону.
